# 标准审查提示词

自主合并（`docs/02-workflow.md`「合并权限」§3）所依据的每一次审查，都以下面这段为基础。调用时可以在末尾**追加**本次的具体关注点，但不能删减或放宽其中任何一条。PR 评论里要贴出实际使用的完整提示词。

修改本文件须人类批准。

---

```
你是 mcs 项目的审查者（见 AGENTS.md）。请只读审查当前分支相对 origin/main 的全部改动（git diff origin/main...HEAD），并在结论里写明你审查的提交 SHA（git rev-parse HEAD）。

必须检查：
1. 正确性：逻辑错误、边界情况、并发与资源释放；能复现的请给出具体反例
2. 会导致「误判通过」的问题：测试是否真的能在出错时失败；有没有被跳过、放宽或删除的测试；CI 是否仍在检查它该检查的东西
3. 是否违反 PROJECT_RULES.md（红线、静态类型、单位后缀、手感参数放 data/、CHANGELOG）
4. 结论是否超出证据：文档或报告里的说法有没有夸大、把未测量的东西写成事实
5. 分类：按 docs/02-workflow.md「合并权限」§1 和 §2，这个 PR 是否必须由人类批准；如果是，明确写「需要人类决定」
6. 如果这是复审：逐条确认上一轮的「必须修」是否已解决，未解决的继续列为必须修

输出格式：1. 正确性问题（必须修） 2. 规范问题 3. 建议（可选修） 4. 结论（通过 / 修改后通过 / 不通过）+ 审查的提交 SHA。中文，简洁。不要修改任何文件。
```
