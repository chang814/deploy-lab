# 灵敏度与 FOV 规格（已审定（GPT）· 待 Claude 审查 · P0-3）

审定范围：本地数学复算与测试规格；本次未联网、未运行 CS2 或 Godot。下文「待测量」项不代表已验证的游戏行为。

## 实现者速查

- 已冻结数学公式：未开镜每 count 角度为 `sensitivity × m_yaw/m_pitch`，360° 距离为 `360 / abs(sensitivity × m_yaw) / DPI × 2.54` cm；适用条件见第 1 节。
- 已冻结投影换算：`vfov = 2 × atan(tan(hfov/2) / aspect)`，反向换算见第 2 节；90° @4:3 是项目基线，CS2 行为待测量。
- 输入约定：原始 counts、不乘帧间隔、float64 累积逻辑角度；Godot 原始输入由 P0-4 验证。
- 暂定常量：`m_yaw = m_pitch = 0.022°/count`、pitch 上下限 ±89°；CS2 当前默认参数与限值待测量。
- 暂定边界行为：内部 pitch 向上为正，逐事件截断并丢弃越界量；CS2 的符号、截断时机与反向响应待测量。
- 开镜待测量：优先证伪社区假设 `Z = ratio × (F_zoom / 90°)`（4:3 水平 FOV），再比较其他候选及各轴、宽高比、过渡期行为。
- 其他待测量：未开镜 FOV、调试变量语义、viewmodel 默认值与投影规则、Godot 实际投影；P0-5 包含 `viewmodel_fov` 控制台读数。

## 1. 视角旋转

未开镜时，每个原始鼠标计数（count）对应的旋转角度大小按以下基线计算（CS2 当前版本默认参数仍需游戏内核对）：

```
yaw_per_count   = sensitivity × m_yaw    （m_yaw 默认 0.022°）
pitch_per_count = sensitivity × m_pitch  （m_pitch 默认 0.022°）
```

- 不使用任何鼠标加速、平滑或基于帧率的缩放
- 输入必须是**原始计数**（Windows Raw Input），不能是经过系统指针速度/加速处理后的像素位移
- 子计数精度不能丢失：每帧累加的角度用 float64 保存
- 上式单位为 °/count；事件角度 = count × 每 count 角度。DPI 只用于物理距离换算，不再乘入旋转公式；不得乘帧间隔。水平与垂直分别使用 `m_yaw`、`m_pitch`。
- 原始 count 可以是整数，但乘系数后产生的小数角度必须保留；浮点输入的小数位移也不得取整。先用 float64 累积逻辑角度，再同步渲染变换，不从低精度渲染变换读回作为下一次累积起点。

### 360° 距离（验收基准）

```
counts_per_360 = 360 / abs(sensitivity × m_yaw)
cm_per_360     = counts_per_360 / DPI × 2.54
```

前提：`DPI > 0` 且 `sensitivity × m_yaw != 0`。零增益没有有限的 360° 距离，应返回明确的无有限值状态，不能除零。负增益只改变旋转方向，距离取正值。以下表格均使用 `m_yaw = 0.022°/count`；标称 DPI 的结果不等同于鼠标实际 DPI 的实测距离。

| DPI | sens | counts/360° | cm/360° |
|---|---|---|---|
| 800 | 1.0 | 16363.64 | 51.95 |
| 400 | 2.0 | 8181.82 | 51.95 |
| 800 | 2.5 | 6545.45 | 20.78 |
| 1600 | 0.8 | 20454.55 | 32.47 |

本地 Python float64 复算（显示 12 位小数，表格保留 2 位）：

| DPI / sens | counts/360° 复算 | cm/360° 复算 | 原表核对 |
|---|---|---|---|
| 800 / 1.0 | 16363.636363636364 | 51.954545454545 | 正确 |
| 400 / 2.0 | 8181.818181818182 | 51.954545454545 | 正确 |
| 800 / 2.5 | 6545.454545454546 | 20.781818181818 | 正确 |
| 1600 / 0.8 | 20454.545454545452 | 32.471590909091 | 正确 |

公式复核：一圈为 360°，除以 °/count 得到 count；再除以 count/inch（DPI），乘 2.54 cm/inch 得到 cm。`counts_per_360` 是连续理论值，不得先取整再算距离；单次整数计数输入无法保证恰好转满一圈。

## 2. 视野（FOV）

未开镜基线采用 **4:3 下的水平 FOV = 90°**，宽屏时保持垂直 FOV 不变，向两侧扩展。`fov_cs_debug` 是调试变量，本次未核实其默认值、特殊值语义及当前版本行为，不再将「变量默认为 90」作为依据，相关 CS2 行为待测量。

```
vfov = 2 × atan( tan(90°/2) × 3/4 ) = 73.7398°
hfov(aspect) = 2 × atan( tan(vfov/2) × aspect )
  16:9  → 106.2602°
  16:10 → 100.3889°
  4:3   → 90°
```

其中 `aspect = 实际渲染视口宽 / 高`，不是拉伸后的显示器宽高比；4:3 拉伸显示仍按 4:3 计算。`tan` 的输入及 `atan` 的输出在代码中使用弧度，最后转为度；适用范围为 `0 < FOV < 180°`、`aspect > 0`。

公式复核：透视投影的半视口宽高比满足 `tan(hfov/2) / tan(vfov/2) = aspect`，两式成立。本地复算 `vfov = 73.739795291688°`；16:9、16:10、4:3 的 `hfov` 分别为 `106.260204708312°`、`100.388857815470°`、`90.000000000000°`。原文仅 16:10 的四位小数舍入有误，其余正确。

Godot 实现目标：`Camera3D.keep_aspect = KEEP_HEIGHT`，`fov = rad_to_deg(2 × atan(3.0/4.0))`，显示值约 `73.7398°`；保留计算精度，Godot 的实际投影行为由实现测试验证。

Viewmodel（第一人称武器）使用独立相机。原草案的「默认 `viewmodel_fov 68`，同样按 4:3 水平换算」本次无法确认，标为**待测量**（包括默认值、角度定义及投影规则），不得把 68 当作已审定的 CS2 默认值；不影响上面的世界相机数学基线。

## 4. 待确认问题及测量方法

### 4.1 开镜灵敏度

可确认的基础角度关系与待测系数分开表示：

```
delta_yaw_deg = delta_count_x × sensitivity × m_yaw × Z
Z = zoom_sensitivity_ratio × K(F_zoom, F_base)  （候选分解，CS2 行为待测量）
```

`Z` 定义为同设置下开镜与未开镜每 count 角度之比；第一式是系数定义。第二式中 ratio 是否线性相乘、`K` 的具体形式及是否有其他依赖，本次不能 100% 确认。未开镜定义 `Z = 1`；不能将 ratio 或任一候选 `K` 直接作为已确认的 CS2 实现。

待区分的候选包括 `K_angle = F_zoom / F_base` 与 `K_tan = tan(F_zoom/2) / tan(F_base/2)`。后者可由「屏幕中心附近单位 count 的投影位移相同」的数学条件推出，但这不证明 CS2 使用它。两候选必须使用同一轴、同一宽高比的 FOV；也须区分 4:3 基准水平角和实际宽屏水平角，不能混用。各武器各级狙击镜的稳定 FOV、是否采用 4:3 基准角、缩放过渡期间的系数、垂直轴是否采用同一 `Z`，均为**待测量**，不填猜测数值。

`K_angle` 标为**首选待验证假设（来源：本轮 Claude 审查提供的社区经验，未核实）**：社区流传的 CS:GO 形式为 `Z = zoom_sensitivity_ratio × (F_zoom / 90°)`，其中 `F_zoom` 为 4:3 基准水平 FOV、`F_base = 90°`。CS2 是否沿用待测量；这是测量顺序的先验，不是采用该公式的依据。下述测量优先尝试证伪该假设，同时比较两候选的残差。

游戏内黑盒验证方法（本地离线练习，不读取、注入或 hook 进程）：

1. 记录游戏 build、武器与开镜级别、分辨率、实际渲染宽高比、DPI、sens、`m_yaw`、`m_pitch`、ratio；使用正常游戏速度，等待开镜动画完全稳定。通过游戏自身控制台可用的角度显示读取视角；命令可用性先现场确认并记录，不能把外部进程读取当作替代。
2. 对准固定地标，用鼠标导轨/标尺重复相同物理水平位移，分别记录未开镜和开镜的起止 yaw；小角度避开 360° 回绕，或明确展开角度。每组至少 5 次，报告中位数与最大偏差。相同 counts 的角度比给出 `Z`；仅用物理位移时存在重复性及实际 DPI 误差，必须记录，不能声称计数级精确。精确 counts 须由独立 Raw Input 验证工具在自身进程记录物理鼠标输入，并验证与游戏接收区间一致，禁止向 CS2 注入输入或读取其进程。
3. 独立测量 FOV：固定站位与 pitch = 0，把同一远处地标依次转到投影视口左右边缘，用游戏自身角度读数之差求水平角；在 4:3 与宽屏重复，并记录截图。狙击镜黑色遮罩的边缘不一定是完整投影视口边缘：若无法确定遮罩与投影范围关系，只能报告可见角宽，完整 FOV 继续标为待测量，不能用它直接拟合上述候选。
4. 在 ratio = 1 及另外两个可设置的非零值重复，检查 `Z / ratio` 是否不变；对每个武器/级别及至少两种宽高比，比较实测 `Z / ratio` 与两候选的残差。只有测量误差小于候选差异且可重复时才能判定，否则仍为待测量。另做垂直小位移与开镜过渡测量；若游戏不提供可用角度读数，保留待测量状态，另行设计可校准的黑盒角度测量，不能仅凭屏幕像素位移认定公式。

### 4.2 pitch 上下限

本项目测试约定：内部 pitch 向上为正、向下为负（鼠标 Y 及 Godot 旋转符号由输入适配层转换），暂采用 `pitch_min_deg = -89`、`pitch_max_deg = 89`，常量放入数据文件。**CS2 当前版本实际上下限及其符号约定待测量**；±89° 是待核实的候选，不是本次游戏实测结论。

Source 系引擎通常采用向下为正的 pitch（本轮审查提供的先验，未核实当前 CS2）；导入或对比采用此约定的 CS2 数值时须翻转符号：`pitch_internal_deg = -pitch_cs2_deg`，增量同理。现场核对符号后，在适配层统一转换。

```
pitch_deg = clamp(pitch_deg + delta_pitch_deg, pitch_min_deg, pitch_max_deg)
```

**项目暂定行为 · 待测量**：上式暂按事件顺序逐次截断，不回绕；越界量丢弃，不保存在隐藏累积器中，因此到达上限后反向移动应立即生效。在这一暂定策略下，不先把一帧内相反方向的事件合计再截断。CS2 是逐事件截断还是按帧累计增量后截断，本次未核实；不得将此策略当作已知的 CS2 行为，须与 ±89° 限值一并实测后决定是否修订。

截断时机测量：在能确认输入事件落入同一帧或不同帧的条件下，对边界处先同向越界、再反向的小位移比较结果，以区分逐事件截断与按帧累计后截断；无法确认事件分组时，截断时机仍标待测量。

验证：本地离线练习记录 build、初始 pitch 与游戏自身角度读数，分别持续上移、下移至读数不再变化，至少重复 5 次；记录上下端点、显示精度和最大偏差。到边界后继续同向移动，再反向小幅移动，验证是否立即离开边界；改变 sens、开镜状态重复。若无足够精度的角度读数，仅截图不能确认 ±89°，仍标待测量。
