- 日期：2026-11-25　测试人：产品负责人　整理：Claude

| 项 | 值 |
|---|---|
| Windows | Windows 11 家庭版 10.0.26300 |
| 鼠标 | ROG Falchion Ace HFX（系统识别的指点设备；回报率未记录） |

## 结果

两次运行（第一次 + 补测）合并比对：**50 个有效轮次、53 条记录，X/Y 两轴计数与 Windows Raw Input 全部完全一致**，所有分组的合计比例为 1.000000，没有出现小数位移，也没有 `relative` 与 `screen_relative` 不一致的事件。3 条记录因点击时鼠标仍在移动被基准判为作废，已补测。

逐条数据见 [`results/2026-11-25/REPORT-data.md`](results/2026-11-25/REPORT-data.md)，原始 CSV 在同一目录。

| 测试 | 条件 | 结论 |
|---|---|---|
| T1 | 慢速 / 快速甩 / 画圈 | 通过 |
| T2 | 指针速度最慢、最快、切换「提高指针精确度」，各快慢两组 | 通过：系统指针设置对 Godot 收到的计数没有任何影响 |
| T3 | 「全屏」组实际记录为**最大化窗口**（`window_mode=2`），不是独占全屏 | 窗口与最大化窗口通过；**独占全屏未测** |

## 结论

**在本次已测条件下**（Windows 11、Godot 4.7.2、`MOUSE_MODE_CAPTURED`、普通窗口与最大化窗口、指针速度最慢/最快、切换「提高指针精确度」），**`InputEventMouseMotion.screen_relative` 的每轮 X/Y 累计值与 Windows Raw Input 的原始计数完全相同**，且没有出现小数位移。

这说明在这些条件下，Godot 收到的位移不受系统指针速度和鼠标加速影响，按轮累计没有丢失或取整。它**不能**证明单个事件层面一定无丢失（比对的是每轮累计值），也不覆盖下面列出的未测条件。

**决定（待人类确认）：** v0.1 暂用 `screen_relative` 驱动视角；是否需要 GDExtension 直接读取 Raw Input，等 #21 补测（独占全屏、显示缩放、高回报率、与 CS2 对照）后再最终确认。

## 未覆盖（转入 #21）

- 独占全屏（F 键切换后应为 `window_mode=4`）
- Windows 显示缩放 125% / 150%
- 高回报率（1000 Hz 以上）快甩
- T5：与 CS2 的 360° 对照（整条链路）

## 测试过程中发现并修正的问题

- 基准计数器收到全系统点击、Godot 只收到自己窗口的点击 → 改为毫秒时间戳配对（本次第一次运行仍是旧格式，按顺序 + 轮号 + 秒级时间核对配对）
- Godot 4.7.2 的 `DirAccess.make_dir_recursive_absolute` 在路径被同名文件占用时仍返回 `OK` → 增加目录存在性检查
- 测试步骤对人不友好 → 增加屏幕顶部的引导模式
